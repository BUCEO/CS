Infraestructura Crítica y Seguridad en Uruguay

Mapeando la norma ISO/IEC 27010 con el Marco de Ciberseguridad de Uruguay (MCU), la Ley N° 18.331 y el despliegue de arquitecturas modernas.

1

El Contexto Uruguayo y Marco Legal

Marco de Ciberseguridad (MCU)

Desarrollado por AGESIC, establece las bases para proteger los activos de información. Funciona en sintonía con la Plataforma de Interoperabilidad (PDI).

  • Foco en resiliencia de infraestructura.
  • Obligatoriedad de notificar al CERTuy.

Ley N° 18.331 (Habeas Data)

Regula el almacenamiento de datos personales. Exige soberanía de datos para información sensible (ej. historia clínica), limitando su alojamiento fuera de Uruguay sin garantías formales.

2

Arquitecturas Híbridas y Soberanía

La solución al dilema legal es una Cloud Híbrida. Mantenemos los datos sensibles (On-Premise) en territorio nacional y delegamos las capas de procesamiento sin estado a la nube pública.

Defensa en Profundidad: IaC y Zero Trust

1. Túnel Seguro (Terraform HCL)

Conexión cifrada (ISO 27010) entre nube y Datacenter uruguayo.

resource "aws_customer_gateway" "datacenter_uruguay" {
  bgp_asn    = 65000
  ip_address = "200.40.X.X"
  type       = "ipsec.1"
  tags = { Compliance = "Ley-18331" }
}

resource "aws_vpn_connection" "tunel_hibrido" {
  vpn_gateway_id      = aws_vpn_gateway.nube.id
  customer_gateway_id = aws_customer_gateway.datacenter_uruguay.id
  type                = "ipsec.1"
  tunnel1_encryption_algorithms = ["AES256"]
}

2. Micro-segmentación (Kubernetes YAML)

Impide acceso directo a la BD desde componentes vulnerados.

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: aislar-bd-ciudadanos
spec:
  podSelector:
    matchLabels:
      app: base-datos-hcen
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: api-gateway-local # Solo confía en el API Gateway

Plantilla ADR (Architecture Decision Record)

Usamos Docs-as-Code. Las decisiones deben registrarse en formato Markdown para las auditorías (ej. URCDP). Esta es la estructura profesional recomendada para justificar decisiones de infraestructura:

1 # ADR 0001: Despliegue de Base de Datos en Datacenter On-Premise (Uruguay)
2 ## 1. Estado
3 **Aceptado** | **Fecha:** 09-08-2026 | **Autores:** [Equipo DevOps]
4 ## 2. Contexto (El Problema)
5 El proyecto requiere almacenar información médica (PII). El equipo prefiere Amazon RDS por su escalabilidad. Sin embargo, la Ley N° 18.331 impone restricciones sobre la transferencia internacional de datos sensibles, requiriendo que permanezcan bajo soberanía nacional y estricto control.
6 ## 3. Decisión
7 Desplegaremos nube híbrida. La Base de Datos (PostgreSQL) se alojará en un clúster local (Datacenter de Antel, Pando). El Frontend se desplegará en AWS. La comunicación se realizará exclusivamente mediante un túnel VPN IPSec (AES-256) cumpliendo con la norma ISO 27010.
8 ## 4. Consecuencias
9
10 ### Positivas:
11 * Cumplimiento estricto del MCU y Ley 18.331.
12 * Aislamiento total de los datos sensibles (Zero Trust) ante posibles brechas en el frontend.
13
14 ### Negativas (Riesgos asumidos):
15 * Mayor complejidad operativa (gestión de backups locales en lugar de AWS automatizado).
16 * Latencia de red añadida (20-40ms) por el túnel VPN internacional.
